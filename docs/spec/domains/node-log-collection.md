# 节点日志采集

本文是 `backend/internal/nodelogs` 及其拥有的 `sshutil` 执行生命周期、采集游标和调度规则的唯一领域合同。凭据使用遵循[凭据与访问](credentials-access.md)，通用日志脱敏遵循[后端日志规范](../backend/logging-guidelines.md)。

## 执行与持久化

- 在解析凭据或执行 SSH 前验证超时和输出上限均为正数。一个操作 context 覆盖拨号、创建 session、启动命令、读取和等待；取消后关闭本次操作拥有的 transport，等待所有执行 goroutine 退出后才返回。
- 复用共享 SSH 执行实现。严格 transport 所有权必须显式启用，不能关闭其他调用方共享的 client。
- 输出恰好达到字节上限合法，多一个字节返回可识别的输出超限错误。失败、取消或截断结果不能进入解析及持久化。
- 明确的远端非零退出码可按兼容合同保留完整且未超限的 stdout；缺失退出状态、transport 错误或读取错误均为失败。日志协议自身仍须校验成功标记，不能把失败命令残留的 stdout 当成成功数据。
- 取消、deadline 和输出超限保留 `errors.Is` 分类。日志及凭据审计不包含命令、输出、路径或原始 transport 错误。
- fetch 失败时不插入任何日志行，不修改任何既有游标；成功后按脱敏、插入日志、保存游标的既有顺序处理。

## Journal 恢复与脚本协议

- 恢复窗口限定为最近 1 小时，每批最多 200 条。首次、缺失、年龄未知或过期游标从窗口内最新 200 条开始；有效近期游标从旧到新继续，超过 200 条时分批追赶。
- 最近一次轮询时间不能证明游标对应的 journal 事件仍在窗口内。复用游标表既有时间字段，无需删游标、改 schema 或清理远端 journal；禁止无界回放数月历史。
- 成功的空重置不能恢复旧 token；fetch 失败保留现有日志和所有游标。滚动窗口外历史不会自动补采。
- 成功持久化后才记录有意丢弃旧窗口的安全观测信息；无证据时不宣称精确跳过条数或完整连续历史。
- 协议分隔符使用带引号的 `printf` 输出，不能直接作为 shell 源码。解析前要求完整成功 framing；隐藏 stderr 或通用 runner 保留非零退出 stdout 都不能把 journal 失败变成成功空结果。
- 兼容旧版 systemd：不能假定时间窗口与 cursor 参数可组合，也不能假定不同 seek 模式下行数限制的方向相同。以生成的 POSIX shell 实际执行结果验证。
- retention 只控制已存日志删除，不控制补采范围。空文件白名单是有效的仅 journal 配置，不因此删除已有存储日志或远端 journal。

## 调度、停止与界面

- 入队前认领节点；同一节点最多一个排队或执行任务。拒绝入队必须撤销认领，worker 所有退出路径通过 defer 释放。
- SSH/数据库工作期间不持有状态锁。每次调度中队列满最多输出一条汇总警告，包含数量和队列深度/容量。
- shutdown 独立拥有取消能力；只有一个 owner 关闭 jobs channel。完成意味着所有 worker 已退出。重复 shutdown、Run 前 shutdown 均安全；调用方超时是错误，不代表 worker 已退出；停止后不重启 scheduler。
- 调度指标不增加 node/path/host 标签。拒绝原因是闭合集合 `full|shutdown`，fetch 失败区分 timeout、cancel、output limit。
- 日志展示和 API 不得暗示已恢复窗口外历史；采集启用状态与数据是否连续是独立事实。修改读取端时继续使用现有认证、节点权限和 API mapper，不额外公开内部游标或 SSH 信息。

## 必须覆盖的回归

使用测试控制的 channel 阻塞 Start/read/Wait、transport close 与 worker completion；覆盖上限/上限加一、非零退出/缺失状态、全部认领释放路径、队列恢复、并发及幂等 shutdown、失败时游标不变且零插入。

恢复用例覆盖首次、过期、近期及已 vacuum 的游标，空重置后新增日志，连续多批超过 200 条，轮询时间近期但事件已过窗口，journal/file 混合源、shell 引号、命令失败及 framing 不完整。生成脚本必须在确定性的命令夹具和临时文件上执行。重复执行 nodelogs 测试并运行 race、相关 sshutil、credentialaudit、生命周期测试和后端门禁。

代码、CI 和镜像发布不等于生产恢复验收。升级前保全数据库、密钥、日志与游标并停止旧采集进程；单独核对已部署镜像及配置，经授权先观察一个低风险节点至少两个周期，再扩大范围。回退到存在采集缺陷的镜像前先关闭受影响采集源，不能通过删除游标恢复。
