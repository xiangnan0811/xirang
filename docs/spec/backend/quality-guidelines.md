# 后端代码质量

## 通用实现要求

保持 Go/Gin/GORM 现有风格，编辑 Go 文件后执行 gofmt。API 响应、数据库、安全和日志分别遵循[错误处理](error-handling.md)、[数据库](database-guidelines.md)、[领域合同](../domains/README.md)及[日志](logging-guidelines.md)，不在此重复各资源规则。

- 所有数据库、SSH、文件、加密、JSON 编解码和迁移错误都必须处理；不能把无法确认的远程结果当成功。
- 动态设置必须注册在 `settings.Service` 中，经服务按 DB → 环境变量 → 默认值解析；已有动态键不能在调用点直接读取环境变量。敏感设置标记 `Sensitive: true` 并加入相关加密迁移覆盖。
- 设置读失败不能用 env/default 覆盖仍可用的旧缓存；有 stale cache 时保留其值。动态配置切换的事务、锁和补偿遵守所属领域合同。
- 验证资源 ID 和输入后再写入。跨资源状态变化使用事务，异步任务和 goroutine 必须能取消、停止并等待结束。
- 优先复用标准库和现有服务/辅助函数，不为小功能引入新依赖，不因相似名称删除仍服务于现有功能的内部代码。
- 改动 API、模型、环境变量、迁移或部署行为时同步对应唯一主文；文档检查与完整交付命令见[贡献指南](../../../CONTRIBUTING.md)。
- 新增路由遵循[路由注册与认证边界](directory-structure.md#路由注册与认证边界)；用户可见通知、错误及运行证据遵循[共享脱敏](logging-guidelines.md#用户可见文本的共享脱敏)，审查不能只检查进程日志。

## 测试原则

行为变化添加或更新包级回归。Handler 测试校验状态与响应封装；数据库测试覆盖空结果和错误；SSH 认证、路径验证、加密、RBAC、所有权必须有明确拒绝用例。授权测试经过实际路由的认证和权限中间件，不能只有绕过中间件的 Handler 测试；权限矩阵和前端可见性由[领域合同](../domains/README.md)定义。

测试替身应保留生产依赖图、回调顺序、事务和失败边界；不允许用手工构造的消费者数据替代真实生产者输出，造成跨层合同错误仍然通过。源代码/AST 边界测试适合保护包依赖或禁止调用，不能替代运行时行为验证。

### 逻辑时钟

相关持久化行必须共享一个逻辑时间源。注入 `Now` 后，fixture 从同一时钟派生 lease、TTL、重试和 deadline；不要再调用真实 `time.Now()` 导致秒/毫秒边界上的不可能顺序。需要时间推进时显式修改测试拥有的时钟变量，各服务继续引用它。

时序失败先确定性复现边界，再运行聚焦的重复和 race 检查；不得降低生产 invariant 或靠重跑 CI 掩盖 fixture 错误。

### 取消与重试

无同步的真实 deadline 可能在首次操作前后到期，不能仅凭名义间隔断言一定发生第二次尝试。若测试需要证明操作确实执行且取消阻止达到重试上限，先确保操作进入，再断言 `attempts > 0 && attempts < retryCap` 和预期 context 错误。确切次数或取消阶段需要测试 channel/显式 cancel 同步。重复和 race 验证保留上下界，不能只检查错误文本。

### 异步状态

触发器返回后，持久化 ID、TaskID、TriggerType 等稳定字段可以精确断言；状态可能已经从 pending 推进，不能无同步要求首次读取仍为 pending。通过显式同步断言最终状态，或断言实际状态机允许的可见集合。验证返回 ID 对应真实持久化行，非法状态始终失败。

### 跨实例竞争

真正的竞争测试要让持有者事务保持未提交，直到竞争者到达同一数据库锁边界。SQLite 可观察 BUSY/LOCKED；PostgreSQL 可校验 `wait_event_type='Lock'` 和 `pg_blocking_pids` 中的准确持有者 PID。共享起跑 channel 或预先顺序插入数据不能单独证明跨实例互斥。

## API 退役

退役协议已决定移除路由时，同时删除 Router 注册和不再使用的 Handler 构造；仅当无其他活跃引用时删除 Handler 文件。移除只服务该 API 的前端 wrapper、类型、状态、effect、UI 及失效文案，保留替代路由和仍被使用的内部 helper。

更新公开文档及 Swagger，不得继续将已移除或返回 410 的 API 写成正常可用。优先 `make swag-init`；本地缺少工具时只精确清理对应生成 path 块，并在验证说明中记录缺口。搜索完整旧路径、wrapper、Handler 类型/构造及失效 i18n key，区分生成输出和有意保留的替代实现。

测试断言旧路由不再注册、替代路由仍存在，覆盖原消费者行为。既定保留路由并返回 410 的兼容边界按领域合同测试，不能误删。后端检查及涉及前端时的完整 `npm run check` 仍由贡献指南要求。

## 测试凭据

模拟秘密的字面量使用 `FAKE_` 前缀和 `_FOR_TEST_ONLY` 后缀，便于人和扫描器识别，例如 `FAKE_METRICS_TOKEN_FOR_TEST_ONLY`。匹配的 Base64、hex、hash 从同一假值现算，不复制外部示例中的高熵值。环境示例优先使用 `<set-strong-random-token>` 一类明确占位符。命名降低误报风险，但不保证任何秘密扫描器自动放行；提交审查仍需确认无真实凭据。

测试初始化要明确设置自身需要的 `APP_ENV=development` 或假加密密钥，并使用相应测试重置入口，不依赖开发者 shell 的偶然环境。
