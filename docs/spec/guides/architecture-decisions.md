# 产品与兼容性决策

## 产品范围

息壤面向个人运维者和小团队，优先降低部署负担、保持兼容并控制变更范围。保留安全态势提示卡和破坏性操作的轻量确认。企业策略、设备信任治理、全面 Vault/KMS、SSH CA、命令审批引擎及会话录制平台不属于默认产品方向；如需引入，应有明确需求。这不削弱现有安全控制，也不删除已支持的集成。

备份资产浏览器提供运维能力，不扩展成可写的通用文件共享或同步产品。产物来源由 Repository 与 RecoveryPoint 身份确立，不能用 TaskRun 身份或目录时间戳代替。跨层行为以[领域合同](../domains/README.md)为准。

## 兼容性边界

- 保持当前 WebSocket 协议；通用协议重构不是默认维护范围。
- KDF salt 迁移需要独立的威胁模型、数据迁移和兼容设计，不能把过去延期的事项当成自动生效的任务。
- 不以全面消除旧 `Printf` 调用为目标。保留必要诊断，以及明确发生在 logger 初始化前的配置日志；新日志遵循[后端日志约定](../backend/logging-guidelines.md)。

## 决策与验收证据

历史提案、阶段状态和旧清单不覆盖当前合同，也不会自动重开已完成事项。验收必须注明候选、环境、范围和时间；仓库测试、CI/镜像交付、用户主机观察是不同证据。某个节点或某种采集源通过，不能推广为所有节点日志通过；备份资产功能验收不等于生产故障注入或百万规模验证。

版本事件查阅 [CHANGELOG](../../../CHANGELOG.md) 和对应 GitHub Release；已删除文档的论证可从 Git 历史按需追溯。当前文档不维护生产验收日期或完成状态副本。
