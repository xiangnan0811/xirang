# 代理协作与验证

## 权威与原生入口

checkout 的根 `AGENTS.md` 及适用子目录入口定义项目权威。各工具使用自身的指令、
技能、角色和权限机制；共享 harness 技能源不授权导入其他工具的运行时设置。

OMP 的项目 `.omp/AGENTS.md` 引入根权威；OMP 的 Advisor 意见不能替代独立审查。
Claude Code 的 `CLAUDE.md` 只保留 `@AGENTS.md`，通过原生导入维持单一项目权威，
不依赖 AGENTS fallback 插件（包括第三方 provider 受限的会话）。支持某版本不能证明 fallback 已激活。
首次从子目录或 worktree 进入时，Claude Code 可能要求批准导入起始目录之外的根文件；
只通过原生提示批准该项目的预期导入，并核对原生来源列表中的入口和被导入权威。

从子目录或 worktree 进入时先解析当前 Git 根，再读取合同或运行命令；工作目录和
验证命令见 [贡献指南](../../../CONTRIBUTING.md)。私有 profile 建议不能替代项目门禁。

领域导航以[领域合同索引](../domains/README.md)为准：节点系统日志已退役，不再加载其旧合同；保留的任务日志与凭据审计分别按任务、凭据领域读取。根入口的这次导航收缩不改变原生加载、独立审查或候选证据规则。

## 并行工作与独立审查

- 主代理负责范围、决策、集成、已授权修复和最终验证。非平凡工作在有益时采用有界
  原生委派；小改动或明确要求直接处理的请求直接执行。
- 实施代理具有互不重叠的文件所有权、明确要求及合同指针，可以修改指定文件并执行
  相关检查；须适应其他工作者的变更，不得恢复无关改动。
- 调查者和独立审查者保持只读，不继续委派，在会话返回结论，无需任务目录。
- 交付非平凡代码、安全或兼容变更、代理治理或加载变更前，须对同一集成候选取得
  独立审查。审查者不得参与该候选的实施或自行修复；主代理自审和实施者自行修复
  不能替代独立审查。
- 审查方式由当前工具按其原生能力和配置决定。
- 每轮提供基线、候选范围、需求与验收证据。主代理协调发现并修复已授权问题。
  修复复审只验证发现 ID 及直接影响；除非候选或证据实质变化，不重启完整发现轮。
- 缺少必要审查或原生平台证据仍是未完成要求；如实报告能力限制，不用自审替代独立性。

## 恢复与证据复用

恢复状态可选且私有，标识仓库、checkout/worktree、模块和目标，不按最新时间选取其他
工作区记录；不恢复已完成或取消任务。历史行动前重新确认当前合同和工作内容。

证据绑定基线版本、选定路径、实际暂存 blob、所需未暂存/未跟踪内容，以及相关运行时
和配置条件。相同 HEAD 不能覆盖脏工作区；部分暂存或候选/条件变化使相关检查失效，
未变的有效证据可复用。只读评估仅做只读索引比较，不暂存、不建临时 Git 索引、不写私有状态。

获授权提交前核对范围、合同同步、独立审查、测试构建和适用验收；在范围内修复并重跑
受影响检查。暂存或格式化后重核最终索引。证据留在会话或已有私有状态，不写仓库过程日志。

## 加载验证与隔离

更改加载或编排后，按受影响的工具、入口和工作目录确定验收范围，在对应工具的
新原生会话中验证根目录、模块或 worktree 的实际加载。使用普通短请求，不提供
预期文件或迁移提示来引导通过；结合工具提供的来源信息和实际工具事件核对生效规则，
区分发现、禁用或被遮蔽、选中来源和实际注入，明确未验证的范围。

切换 profile/worktree 不证明隔离；核对解析后的用户/配置目录、技能/扩展、私有状态、
Git common-directory 及共享服务。静态辅助检查或单平台通过不代表其他平台原生验收。
临时探针置于项目外并在验收后清除，持久项目要求由本合同维护。
