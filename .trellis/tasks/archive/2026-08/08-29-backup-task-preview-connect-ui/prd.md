# 备份任务首次接入文件预览入口

## Goal

在备份任务列表中为仍处于 `legacy_mutable` 模式的 Rsync 任务提供安全、可发现的“接入或刷新文件预览”入口。入口复用现有由 Task 派生的 Connect API，不要求用户填写仓库定位符或凭据；连接成功后主动推动目录索引收敛，并在同一对话框中展示从探测、索引到可浏览的状态和精确文件浏览入口。

## Background

- 已恢复的生产验收记录显示：Task 3 因已有受管仓库关联而能够预览；Tasks 1、4–13 没有等价关联，其中 Task 4 还存在失败状态。该生产事实来自旧会话恢复，本轮规划没有重新探测线上环境。
- 现有 Rsync“启用多版本模式”对话框只用于迁移已经连接的旧 Rsync 仓库，要求匹配旧关联；它不是首次接入文件预览的入口。
- 后端已经提供 `POST /api/v1/backup-repositories/connect`，可仅凭 `task_id` 从任务、节点和凭据中派生受管仓库关系，并执行有界只读探测。
- 现有目录工作器按周期扫描，默认收敛时间可能达到约 15 分钟。用户完成接入后需要即时反馈，但主动唤醒不得破坏周期扫描的公平性和停机语义。

## Locked Product Decisions

1. 在任务的表格和卡片操作区增加独立入口，文案固定为“接入或刷新文件预览”；不根据当前 Task DTO 猜测“未连接”。
2. 入口仅对管理员且执行器为 Rsync、发布模式为 `legacy_mutable` 的任务显示；受管/多版本 Rsync 与 Rclone 不显示。
3. 暂停或禁用的任务仍可接入；任务正在运行、重试或存在活动运行时，入口保持可见但禁用并解释原因。
4. 客户端只提交 `task_id`，不收集或提交定位符、用户名、密码、密钥等敏感数据。
5. 接入不启用多版本、不中断任务、不修改或删除备份文件，也不在目录失败时自动断开仓库。
6. 连接成功后由后端以尽力而为、非阻塞方式唤醒目录工作器；周期扫描仍是最终兜底。
7. 对话框轮询该次连接返回的精确可变恢复点；目录完整且允许列目录时即可进入文件工作区，空目录也是合法的就绪结果。

## Requirements

### R1 — 可发现性与资格判断

- 表格与网格视图必须使用一致的资格判断和动作回调，避免两个视图行为漂移。
- 入口必须使用区别于“启用多版本”的图标、标签和辅助说明。
- 权限判断必须与后端 `backup_repositories:manage` 的管理员边界保持一致；Viewer 与 Operator 不得看到入口。
- 活动运行状态只作为客户端防误触保护，后端仍是权限、关联和状态合法性的最终裁决者。

### R2 — 安全、幂等的任务派生连接

- 调用现有 Connect API 时请求体只能包含任务标识。
- 已有关联的任务重复调用应安全地解析或刷新现有关联，而不是创建冲突关系。
- 任何探测或事务失败都必须按现有安全错误边界返回；不得泄漏原始定位符、凭据或内部错误细节。
- Connect 不得成为启用 Rsync 多版本模式的旁路；受管 Rsync 仍必须走现有激活流程。

### R3 — 目录索引即时收敛

- 成功提交并产生可用 mutable point 后，Connect 服务请求目录工作器唤醒一次。
- 唤醒必须是容量一、非阻塞、可合并的提示；队列已满、工作器停止或拒绝唤醒不能把已成功的 Connect 反转成失败。
- 探测失败、事务失败或没有可索引 mutable point 时不得唤醒。
- 在扫描期间到达的唤醒不得丢失；本轮扫描完成后必须再执行一轮，以发现扫描候选快照之后新提交的恢复点。
- 周期计时器不得因连续唤醒而不断重置；持续唤醒流量不能饿死后续到期候选。
- Run 前的唤醒应由初始扫描吸收，避免无意义的紧邻重复扫描；停止时必须取消并等待所有活动扫描退出。

### R4 — 类型安全的响应边界

- 前端连接结果必须同时解析仓库与可选 mutable point，并兼容现存 Go 序列化可能产生的 `MutablePoint` 以及约定式 `mutable_point`。
- 恢复点核心字段映射应由恢复点 API 共享；Connect 返回的快照不包含 catalog 投影，不能用断言伪装成完整恢复点。
- 缺失、空值或畸形 mutable point 必须安全阻断轮询，不得用不确定的点 ID 发起查询。
- 原始 snake_case 响应不得越过 API mapper 进入组件。

### R5 — 有界状态机与轮询

- 对话框至少呈现：待确认、正在连接/探测、正在建立索引、可浏览、失败/阻断、后台继续索引（前台超时）状态。
- 连接成功且返回有效 mutable point 后，每 2 秒查询一次该点的目录状态，最长约 2 分钟。
- 当 generation 完成、coverage 完整、内容可用且具有 list 权限时视为可浏览；不得要求 preview 权限，也不得要求条目数大于零。
- catalog 失败、部分覆盖、不可用或 mapper 拒绝必须转成稳定、本地化、无内部细节的 UI 状态。
- 超时只结束前台等待，不得断开仓库；应明确提示后台索引继续，并允许用户关闭或稍后查看。
- 关闭对话框、切换任务、令牌变化或组件卸载时必须取消在途请求和后续轮询。

### R6 — 精确导航与无障碍

- 就绪动作必须使用 `backupAssetsRecoveryPointHref(taskId, pointId)` 进入此次连接返回点的精确文件工作区。
- 对话框使用现有 UI primitive，保持键盘焦点和关闭语义；状态变化通过 `aria-live` 宣告。
- 禁用动作必须有可读取的原因，图标按钮必须有精确的可访问名称。
- 中文为默认语言，同时补齐英文翻译，不得硬编码用户可见文案。

### R7 — 隐私与非泄漏

- UI、日志、测试快照、错误提示和审计投影中不得出现原始仓库定位符、凭据、票据、密钥或探测证明。
- 不增加客户端输入敏感连接参数的表单，不增加公共目录重建端点。
- 接入与索引都是只读观察链路，不得改变提供方数据或备份任务的版本化模式。

### R8 — 验证与交付

- 后端以 TDD 覆盖唤醒公平性、生命周期、Connect 提交边界和生产组合 wiring。
- 前端以 TDD 覆盖 mapper、对话框状态机、取消、超时、空目录就绪、表格/网格权限及禁用条件。
- 完成实现后运行聚焦测试、race/repeat 检查、前端完整 gate、项目完整 gate、diff/privacy 扫描。
- 通过专用分支、PR、所需 CI 和合并后自动化完成交付；若没有版本发布，必须明确记录未触发 Release/Docker 发布是预期结果。

## Out of Scope

- 修改 Task API 以投影仓库关联状态。
- 自动批量连接全部历史任务。
- 新增或修改数据库 schema、迁移、公共路由、Swagger 合约或部署配置。
- 启用 Rsync 多版本、迁移旧链接、修改提供方数据或自动断开连接。
- 在本任务中重做完整仓库管理页或搜索索引的即时唤醒机制。

## Acceptance Criteria

- [x] AC1：管理员在表格和网格中都能看到 legacy mutable Rsync 的“接入或刷新文件预览”，非管理员、受管 Rsync 与 Rclone 看不到。
- [x] AC2：暂停/禁用任务仍可操作；运行中、重试中或存在活动运行的任务保持可见但禁用，并提供本地化原因。
- [x] AC3：确认操作只向现有 Connect API 发送 `{task_id}`，无任何原始定位符或凭据输入/输出。
- [x] AC4：重复 Connect 保持安全；不启用多版本，不改删备份文件，不在目录失败时自动断开。
- [x] AC5：成功事务且返回 mutable point 时请求一次非阻塞目录唤醒；失败或无点时不请求；唤醒拒绝不影响 Connect 成功。
- [x] AC6：目录工作器满足唤醒合并、扫描中唤醒不丢、周期不被推迟/饿死、Run 前吸收和停机回收契约。
- [x] AC7：前端类型边界兼容 `MutablePoint`/`mutable_point`，复用恢复点核心 mapper，并对缺失或畸形点 fail closed。
- [x] AC8：对话框完整覆盖连接、索引、就绪、失败/阻断和前台超时状态；每 2 秒轮询且约 2 分钟有界，生命周期变化会取消请求。
- [x] AC9：完整空目录也能就绪；就绪按钮进入该 task/point 的精确恢复点工作区。
- [x] AC10：中文和英文文案、键盘/焦点、`aria-live`、禁用说明和图标可访问名称均通过测试。
- [ ] AC11：后端聚焦/race/repeat、前端 `env -u NODE_ENV npm run check`、项目 `make check` 以及隐私/diff 检查全部通过。
- [x] AC12：PR 必需 CI 通过，合并后发布自动化已核对，并记录是否预期产生正式版本与镜像。
